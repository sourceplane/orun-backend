## Summary

Implemented the local namespace model for CLI `orun run --remote-state` sessions, as specified in Task 0012.3.1. CLI sessions now auto-resolve a `local:user:<id>:repo:<id>` namespace via `POST /v1/accounts/repos/link` instead of requiring a pre-cached `repo:` namespace ID.

The previously failing command now works:
```
orun run --remote-state -i examples/intent.yaml --dry-run --backend-url https://orun-api.sourceplane.ai
```

---

## Changes

### `internal/cliauth/backend.go`
- Expanded `LinkRepoFromSessionResponse` with `NamespaceKind`, `RepoID`, `RepoFullName`.
- `LinkRepoFromSession` validates `namespaceKind == "local"` and returns `*APIError{Code: "INVALID_RESPONSE"}` for old backend versions.

### `internal/cliauth/types.go`
- Added `NamespaceKind` and `RepoID` to `RepoLink` for config persistence.

### `cmd/orun/remote_config.go`
- `resolveRepoContext`: invalidates cached namespace IDs that don't have `local:` prefix (pre-0012.2.1 stale entries).
- `persistRepoLink`: signature changed from `(backendURL, repo, namespaceID string)` to `(backendURL string, repo *repoContext, resp *cliauth.LinkRepoFromSessionResponse)`; stores full metadata including `NamespaceKind` and `RepoID`.
- `autoResolveNamespace`: return type changed from `(string, error)` to `(*cliauth.LinkRepoFromSessionResponse, error)`.

### `internal/remotestate/client.go`
- Added `RepoFullName string` to `CreateRunRequest`.

### `internal/statebackend/backend.go` + `remote.go`
- Added `RepoFullName string` to `InitRunOptions`; threaded through to `CreateRunRequest`.

### `cmd/orun/command_run.go`
- Passes `repoFullName` (from `repo.RepoFullName`) in `InitRunOptions` for non-GHA sessions.
- Uses `resolved.NamespaceID` from the new return type.

### `cmd/orun/command_cloud.go`
- Updated `orun cloud link` to pass `linked` (full response) to `persistRepoLink`.

### `examples/remote-state-matrix/run-local-harness.sh`
- Preflight `(not linked)` check is now `info` (not a hard `fail`) since auto-resolution handles it.
- Missing "Current Git remote:" is also non-fatal now.
