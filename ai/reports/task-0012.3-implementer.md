# Task 0012.3 Implementer Report

## Summary

Wired the `POST /v1/accounts/repos/link` endpoint (Task 0012.2) into the
`sourceplane/orun` CLI so that local `orun run --remote-state` auto-resolves
the repo namespace without requiring a prior `orun cloud link`.

The user-reported error is eliminated for authenticated local runs with a GitHub
remote and a session that has namespace access:

**Before:** `Error: initializing remote run: init run: create run: Session creates require namespaceId (code: INVALID_REQUEST)`

**After:** The CLI calls `POST /v1/accounts/repos/link`, persists the returned
namespace ID, and passes it to `POST /v1/runs`.

## Root Cause Fixed

`setupRemoteStateHooks` checked the local config cache for a namespace ID.
When the cache was cold (no prior `orun cloud link`), `namespaceID` was empty
and `POST /v1/runs` failed with `INVALID_REQUEST`. The fix inserts an
auto-resolve step that calls the session link endpoint when the cache is cold
and we are outside GitHub Actions.

## CLI Namespace Resolution Flow

```
orun run --remote-state (outside GHA)
  └─ resolveRepoContext           // check ~/.orun/config.yaml cache
     └─ cache miss
        └─ ORUN_TOKEN set?        // → error: pre-cache required
        └─ no GitHub remote?      // → error: GitHub remote needed
        └─ autoResolveNamespace
              └─ SessionTokenSource.Token()   // refresh if needed
              └─ BackendClient.LinkRepoFromSession(token, "owner/repo")
                    → POST /v1/accounts/repos/link
              └─ returns namespaceID
           └─ persistRepoLink()   // write ~/.orun/config.yaml
  └─ POST /v1/runs with namespaceId
```

## `orun cloud link`

Rewritten to use `LinkRepoFromSession` directly:

1. Loads and refreshes the local Orun CLI session.
2. Calls `POST /v1/accounts/repos/link` with `{ repoFullName }`.
3. Persists the returned namespace ID and backend URL in `~/.orun/config.yaml`.
4. Prints a concise success summary.

No longer requires the repo to be pre-linked via the Orun dashboard or a
GitHub PAT. Falls back with user-friendly messages for `NOT_FOUND` (re-login),
`FORBIDDEN` (re-auth or admin access), and `HTTP_404` (backend not updated).

## `orun run --remote-state`

`setupRemoteStateHooks` gains the auto-resolve path:

- If `namespaceID` is empty and outside GHA:
  - `ORUN_TOKEN` set → clear error directing user to pre-cache with `orun cloud link`.
  - No GitHub remote → clear error explaining the requirement.
  - Otherwise → call `autoResolveNamespace`, persist result, proceed.
- `ctx` lifted to top of function to be shared across the auto-resolve and
  `ResolveTokenSource` calls.

## ORUN_TOKEN Behavior

`ORUN_TOKEN` is a static bearer token. The `POST /v1/accounts/repos/link`
endpoint requires `sessionKind=cli`, so a static token cannot resolve namespace
identity. When `ORUN_TOKEN` is set and no cached namespace link exists, the CLI
returns:

```
local remote-state with ORUN_TOKEN requires a pre-linked namespace;
run `orun cloud link --backend-url <URL>` first to cache the namespace ID
```

If a cached link exists in `~/.orun/config.yaml` from a prior `orun cloud link`,
the `ORUN_TOKEN` path proceeds normally.
