## Security Findings

No security failures found.

### Invariant 1 — CLI session never uses canonical repo namespace

`resolveRepoContext` (`remote_config.go:67-73`) invalidates any cached namespace ID that does not have the `local:` prefix. Stale `repo:` IDs from pre-0012.2.1 cache entries are silently cleared and force a re-link. Enforced in `TestInvalidateCanonicalCachedNamespace`.

### Invariant 2 — `LinkRepoFromSession` rejects non-local responses

`backend.go:193-199` returns `*APIError{Code: "INVALID_RESPONSE"}` if the backend returns `namespaceKind != "local"`. This guards against old backend versions returning canonical namespace IDs. Enforced in `TestLinkRepoFromSession_NonLocalKindRejected`.

### Invariant 3 — `ORUN_TOKEN` cannot infer repo identity

`command_run.go:327-333`: if `ORUN_TOKEN` is set outside GitHub Actions, the CLI requires a pre-cached namespace (`orun cloud link`) rather than calling the session link endpoint. Prevents arbitrary token → namespace inference.

### Invariant 4 — GitHub Actions path unchanged

`resolveRepoContext` errors are swallowed in GHA context (`command_run.go:315-318`). `repoFullName` is only set for non-GHA runs (`command_run.go:371-373`). `autoResolveNamespace` is only called when not in GHA and `ORUN_TOKEN` is not set. OIDC behavior is fully unaffected.

### Invariant 5 — No old `allowedNamespaceIds` pattern for local runs

`AllowedNamespaceIDs` remains in `Credentials` struct for backward-compatible storage, but is never consulted to determine namespace for local remote-state runs. New code uses exclusively the server-derived `local:` ID from the link response.

### Invariant 6 — No GitHub PAT promotion

`command_cloud.go` Long description: "No GitHub PAT or OAuth token is required". No code path prompts for or suggests a GitHub PAT.
