# Task 0012.2.1 Implementer Report

## Summary

Rewrote the namespace trust model for CLI sessions to close the security vulnerability introduced
in commit `61f2ba8`. CLI users now receive isolated `local:user:<githubUserId>:repo:<repoId>`
namespaces derived deterministically from their immutable GitHub user ID. They cannot reach
canonical `repo:` namespaces at all.

## Root Cause

Commit `61f2ba8` removed the `allowedNamespaceIds` guard from `handleLinkRepoFromSession` to fix
a real problem (stale sessions with missing slugs). But this opened a new vulnerability: any
authenticated CLI user could call `POST /v1/accounts/repos/link` with any `repoFullName`, the
handler would look up that slug in the global `namespaces` table, create an `account_repos` row
linking their account to that namespace, and then create runs in that namespace — including
canonical CI namespaces belonging to other repos or orgs.

## Fix Architecture

Two namespace kinds, never mixed:

| Kind | Format | Who can use |
|------|--------|-------------|
| `repo` | `repo:<githubRepoId>` | OIDC/GitHub Actions tokens only |
| `local` | `local:user:<githubUserId>:repo:<repoId>` | CLI sessions only |

Authorization source for CLI sessions is exclusively the `account_repo_cache` table — populated
from the GitHub token available during login (OAuth or device flow). The global `namespaces` table
is never consulted for CLI namespace resolution.

## Migration

**`migrations/0004_local_namespaces.sql`**:
- `ALTER TABLE accounts ADD COLUMN github_user_id TEXT` — stores immutable GitHub numeric user ID
- `ALTER TABLE namespaces ADD COLUMN namespace_kind TEXT NOT NULL DEFAULT 'repo'` — namespace kind discriminant
- `CREATE TABLE account_repo_cache` — per-account repo registry, the sole authorization source for CLI namespace derivation

## Changes by File

### `packages/types/src/index.ts`
- `Namespace.kind?: "repo" | "local"` discriminant
- `SessionClaims.githubUserId?: string` — propagated from JWT to `RequestContext`
- `CreateRunRequest.repoFullName?: string` — lets CLI identify repo by name rather than namespace ID
- New `LinkRepoFromSessionResponse` type with `namespaceKind: "local"`

### `auth/github-oauth.ts`, `auth/device-flow.ts`
- `OAuthCallbackResult` / `DevicePollSuccessResponse` gain `githubUserId: string`
- Session JWT payload includes `githubUserId: String(user.id)` (numeric GitHub user ID)

### `auth/session.ts`, `auth/index.ts`
- `verifySessionToken` extracts `githubUserId` from JWT claims
- `RequestContext` session variant gains `githubUserId?: string`

### `handlers/auth.ts`
- OAuth callback + device poll: call `getOrCreateAccount(..., githubUserId)` and
  `upsertAccountRepoCache(db, accountId, namespaceSlugs)` to populate the cache
- Token refresh (`handleCliToken`): looks up account by login to include `githubUserId` in
  new access token (since `cli_sessions` table doesn't store it directly)

### `handlers/accounts.ts`
New helpers:
```typescript
upsertAccountRepoCache(db, accountId, repos: NamespaceRef[], now?)
lookupRepoInAccountCache(db, accountId, repoFullName): Promise<AccountRepoCacheRow | null>
lookupRepoInAccountCacheByRepoId(db, accountId, repoId): Promise<AccountRepoCacheRow | null>
```

`handleLinkRepoFromSession` rewritten:
1. Requires `authCtx.githubUserId` or throws `FORBIDDEN` (re-login required)
2. Looks up `repoFullName` in `account_repo_cache` (NOT global `namespaces`)
3. Derives `namespaceId = local:user:<githubUserId>:repo:<repoId>` deterministically
4. Creates namespace with `namespace_kind = 'local'`
5. Returns `{ namespaceKind: "local", namespaceId, namespaceSlug, repoId, repoFullName, linkedAt }`

### `handlers/runs.ts`
CLI session path in `handleCreateRun`:
- Rejects `namespaceId` not starting with `"local:"` immediately (`FORBIDDEN`)
- With `repoFullName`: resolves via `lookupRepoInAccountCache`, derives local namespace ID
- With `namespaceId`: verifies it starts with `local:user:<githubUserId>:repo:` and is in cache
- Dashboard sessions: `FORBIDDEN` (cannot create runs)

### `handlers/jobs.ts`, `handlers/logs.ts`
`resolveNamespaceForMutableAccess` updated:
- After `oidc` branch returns, explicit `type !== "session"` guard narrows TS union (fixes typecheck)
- For CLI sessions: requires `githubUserId`, builds `localPrefix = "local:user:<uid>:repo:"`
- Only searches namespaces matching the caller's local prefix — session cannot reach other users' local namespaces

### `packages/client/src/index.ts`
`linkRepoFromSession` return type updated to `Promise<LinkRepoFromSessionResponse>`.

## Security Invariants Verified by Tests

1. CLI session without `githubUserId` → `FORBIDDEN` with re-login guidance
2. `POST /v1/accounts/repos/link` with unknown `repoFullName` → `NOT_FOUND` (no global fallback)
3. Two users linking the same repo receive **different** `namespaceId` values (`local:user:11111:...` vs `local:user:22222:...`)
4. CLI session cannot create run under canonical `repo:` namespace
5. CLI session cannot create run under another user's `local:user:` namespace
6. Mutable coordination routes (claim/update/heartbeat/log upload) reject CLI sessions not matching the run's local prefix

## Backward Compatibility

- Existing `POST /v1/accounts/repos` (dashboard flow with `X-GitHub-Access-Token`) is unchanged.
- `linkRepo()` internal helper defaults `namespaceKind` to `'repo'` so existing callers are unaffected.
- Old CLI sessions without `githubUserId` in JWT get a clear `FORBIDDEN` error with re-login instructions.
- No data migration needed: `namespace_kind` defaults to `'repo'`, so existing rows remain valid.
