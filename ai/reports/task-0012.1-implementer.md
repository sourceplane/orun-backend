## Duplicate-Claim Proof

**`harness_helpers.sh: assert_exactly_one_duplicate_claimant JOB_ID MARKER EXPECTED_COUNT LOG_A LOG_B`**

The function:
1. Counts `MARKER` lines in `LOG_A` and `LOG_B` separately using `grep -c ... || true` (to avoid the `grep -c` exit-1-on-no-match doubling bug on macOS).
2. Accepts exactly two cases:
   - `count_a == expected && count_b == 0` → process A executed
   - `count_a == 0 && count_b == expected` → process B executed
3. Fails with printed diagnosis for all other cases:
   - both > 0 → "BOTH processes executed"
   - both == 0 → "NEITHER process executed"
   - partial/unexpected count → "unexpected marker count"
4. On failure, prints both log files.

For the current fixture, `EXPECTED_COUNT=2` (validate + apply steps each emit one `=== SMOKE: foundation` line).

## Preflights and Cleanup

**Preflight checks (in order, before concurrent run):**

1. `command -v "${ORUN_BIN}"` — fail with install instructions if missing
2. `command -v jq` — fail with install instructions if missing
3. `orun auth status --backend-url "$BACKEND_URL"` — fail with `orun auth login` instructions if not logged in; also checks for `(expired)` in the output
4. Repo linkage check — fail with `orun cloud link` instructions if `(not linked)` found in auth status, or if `Current Git remote:` line is absent entirely

**Signal-safe cleanup:**

```bash
HARNESS_PIDS=()
cleanup() {
  for pid in "${HARNESS_PIDS[@]}"; do kill "$pid" 2>/dev/null || true; done
  wait "${HARNESS_PIDS[@]}" 2>/dev/null || true
  rm -rf "${TMPDIR_H:-}"
}
trap cleanup EXIT INT TERM
```

PIDs are added to `HARNESS_PIDS` after each `&` launch and cleared after all `wait` calls complete so the cleanup function does not attempt to kill already-exited processes on normal exit.

## Workflow Assertions

The previous `Assert all jobs succeeded` step only counted `failed` status entries. The new `Assert all expected conformance jobs succeeded` step:

1. Runs `orun get jobs` against the compiled plan to enumerate all expected job IDs (handles the case where the plan is downloaded from the artifact).
2. For each job ID, checks `.state.jobs[$id].status` from `orun status --remote-state --json`.
3. Accepts `success` and `completed` (the canonical completed-success values used by the CLI).
4. Fails immediately if any job is missing (empty status), pending, running, blocked, or any other non-success value.
5. A separate `Verify remote logs (non-empty)` step also asserts that log content is non-empty for `first_job`.

## Assumptions

1. `grep -c pattern file` on macOS exits 1 when no matches found but still prints `0` on stdout. Using `|| true` (not `|| echo 0`) avoids doubling the count in command substitution.
2. `seq 1 0` on macOS counts downward and produces `1\n0\n` — using a `while` loop for `make_log` avoids this cross-platform pitfall.
3. The `assert_exactly_one_duplicate_claimant` expected count of `2` is derived from the fixture's two-step composition (validate + apply, each printing one `=== SMOKE: foundation` line). If the composition steps change, the expected count should be updated accordingly in the harness call.
4. `orun auth status` output format is stable: presence of `(linked)` / `(not linked)` / `Current Git remote:` is sufficient for preflight. This is based on reading `cmd/orun/command_auth.go:runAuthStatus`.
