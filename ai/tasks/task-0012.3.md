# Objective

Make local `orun run --remote-state` auto-detect the current GitHub remote, resolve/link it through the backend CLI session endpoint, persist the repo namespace link locally, and include `namespaceId` when creating the remote run.

The local developer flow should match the GitHub Actions flow in spirit:

```text
GHA:   OIDC token -> backend extracts repo namespace -> create run
Local: CLI session token + git remote -> backend resolves repo namespace -> create run
```

No GitHub PATs, no GitHub OAuth tokens in the CLI, and no mandatory prior dashboard linking for repos that are visible in the CLI session.

# Required Outcomes

## 1. Add CLI Backend Client Method

Update `internal/cliauth/backend.go` with a method for Task 0012.2's endpoint, for example:

```go
LinkRepoFromSession(ctx context.Context, accessToken string, repoFullName string) (*LinkedRepo, error)
```

It should call:

```text
POST /v1/accounts/repos/link
{ "repoFullName": "owner/repo" }
```

Use the same typed backend error parsing as existing auth/account calls.

## 2. Make `orun cloud link` Self-Service

Update `orun cloud link`:

- Detect current GitHub remote.
- Ensure local Orun auth exists and refresh access token if needed.
- Call the new session repo link endpoint.
- Persist `backend.url`, `gitRemote`, `repoFullName`, and `namespaceId` in local config.
- Print a concise success summary.

Fallback behavior:

- If the backend route is missing, tell the user the backend must be updated to Task 0012.2.
- If the session predates namespace slug mapping, tell the user to run `orun auth login` again.
- If the repo is not visible to the Orun session, tell the user which repo was detected and that the GitHub login must have admin access or namespace access.

Do not ask for or accept a GitHub PAT.

## 3. Auto-Resolve Namespace During `orun run --remote-state`

Update the remote-state setup path so local runs do not require a prior manual `orun cloud link`.

Behavior outside GitHub Actions:

1. Detect current GitHub remote and repo full name.
2. Load any cached repo link from `~/.orun/config.yaml`.
3. If a namespace ID is cached, use it.
4. If missing, refresh/load Orun CLI credentials and call `POST /v1/accounts/repos/link`.
5. Persist the returned namespace link.
6. Include `namespaceId` in `POST /v1/runs`.

Behavior in GitHub Actions:

- Keep OIDC behavior unchanged.
- Do not call the session repo link endpoint.
- Do not require local config.

Failure behavior:

- Missing local auth: prompt `orun auth login` or `orun auth login --device`.
- Missing GitHub remote: explain that local remote-state needs a GitHub remote to resolve namespace.
- Backend route missing: explain Task 0012.2 backend deploy is required.
- Repo not visible/authorized: explain which repo was detected and how to re-auth or fix access.
- Do not leak the backend's raw `Session creates require namespaceId` error as the primary user message.

## 4. Keep `ORUN_TOKEN` Behavior Safe

If local remote-state is using `ORUN_TOKEN` outside GitHub Actions, the CLI cannot necessarily call the session repo link endpoint.

Choose a safe behavior and document it:

- either require a cached namespace link or explicit namespace config for `ORUN_TOKEN`, or
- call the endpoint only when the token is known to be an Orun CLI session token.

Do not assume `ORUN_TOKEN` can resolve repo identity without session context.

## 5. Update Harness and Docs

Update local remote-state docs and harness messaging from Task 0012.1:

- `orun cloud link` should become an explicit/manual cache and diagnostic command, not a hard prerequisite when `orun run --remote-state` can auto-resolve the repo.
- The happy path should be:

```bash
orun auth login
orun run --remote-state -i examples/intent.yaml --dry-run
```

- For live execution, omit `--dry-run` only when the user intentionally wants the jobs to execute.
- Explain that GHA uses OIDC and local uses CLI session + Git remote + backend repo resolve.
- Keep dry-run scope honest.
- Keep GitHub PATs out of the normal path.

Update the Task 0012 local harness if its preflight still requires an already-linked local config. The harness may call `orun cloud link` explicitly for diagnostics, but it should not block before giving the auto-resolution path a chance.

## 6. Tests

Add tests for:

- parsing common GitHub remotes still works.
- `orun cloud link` calls the new endpoint and persists the namespace.
- `orun run --remote-state` auto-resolves namespace when no cached link exists.
- cached namespace link avoids unnecessary resolve calls.
- GitHub Actions OIDC path does not call local session link logic.
- missing local auth gives a clear login message.
- backend `NOT_FOUND` for unknown slug produces a re-login/update/access message.
- backend `FORBIDDEN` produces an authorization/access message.
- `ORUN_TOKEN` path behaves according to the safe behavior chosen above.
