# Required Verification Work

## 1. Auth Slug Mapping

Verify OAuth and device login now capture repo slug mappings:

- Admin repos are represented as both namespace ID and slug.
- Bulk upsert into `namespaces` happens during successful CLI auth.
- GitHub OAuth access tokens are discarded after auth.
- Session JWTs do not grow to include unnecessary slug payload if ID-only was the intended token contract.
- Existing dashboard/OAuth behavior is not broken.
- Older sessions without slug rows produce a typed re-login error from the link endpoint.

## 2. New Endpoint Behavior

Verify `POST /v1/accounts/repos/link`:

- Requires session auth.
- Requires CLI session unless a spec proposal explicitly broadened this.
- Validates `repoFullName`.
- Resolves slug case-safely or with a clear documented case policy.
- Creates/reuses `accounts` and `account_repos` rows idempotently.
- Returns `namespaceId`, `namespaceSlug`, and `linkedAt`.
- Rejects missing/invalid JSON with `INVALID_REQUEST`.
- Rejects dashboard sessions with `FORBIDDEN`.
- Rejects unknown slug with `NOT_FOUND` and useful re-login guidance.
- Does not require `X-GitHub-Access-Token`.
- Does not leak D1 details.

Security-critical check:

Task 0012.2 required the resolved namespace ID to be present in `allowedNamespaceIds`. Commit `61f2ba8` appears to remove that check. PASS only if one of these is true:

- the check still exists elsewhere and the commit message is misleading; or
- an accepted proposal/spec update explains why any CLI session may link any known repo slug, with compensating controls; or
- the implementation is changed before PASS to restore an authorization check.

If any CLI session can link any known repo slug solely because the slug exists in D1, FAIL. That would let one authenticated user create remote-state runs under another repo namespace.

## 3. Existing Routes Still Work

Verify:

- Existing `POST /v1/accounts/repos` with `X-GitHub-Access-Token` still works for dashboard/admin linking.
- Existing `GET /v1/accounts/repos` still lists linked repos.
- Existing `DELETE /v1/accounts/repos/:namespaceId` still unlinks only the authenticated account's link.
- `POST /v1/runs` still requires `namespaceId` for session-created runs.
- `POST /v1/runs` accepts a linked/authorized session namespace.
- Dashboard sessions remain read-oriented and cannot claim/update/heartbeat/upload logs.
