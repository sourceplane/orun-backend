# Required Outcomes

## 1. Fix Duplicate-Claim Proof

Replace the current duplicate-count heuristic in `run-local-harness.sh`.

The verifier rejected this logic:

```text
combined foundation marker count > 2 means duplicate execution
```

because one valid execution already prints two `=== SMOKE: foundation` markers.

Implement an assertion that proves exactly one of the two duplicate claimant processes executed the job body.

Minimum acceptable behavior:

- Count foundation smoke markers separately for process A and process B.
- Treat one real execution as the expected marker count for one claimant. Based on current fixture output, that is exactly two `=== SMOKE: foundation` markers.
- PASS only when exactly one claimant log has the expected execution marker count and the other claimant log has zero job-body markers.
- FAIL for all ambiguous cases, including:
  - both claimant logs contain job-body markers
  - neither claimant log contains job-body markers
  - either claimant log contains a partial or unexpected marker count
- Print both claimant logs on failure.

Prefer extracting pure assertion helpers so the guard can test passing and failing synthetic log cases without a live backend. For example:

```text
assert_exactly_one_duplicate_claimant <job-id> <marker> <expected-count> <log-a> <log-b>
```

The exact function name and file layout are up to you, but keep the harness easy to read.

## 2. Add Preflight Checks and Signal-Safe Cleanup

Add explicit preflight checks before launching concurrent job runners.

The harness must fail before the parallel run starts when:

- `ORUN_BIN` cannot be executed or found
- `jq` is missing
- local auth is missing or expired
- local repo linkage is missing or cannot be resolved

Expected user-facing guidance:

- Missing auth: tell the user to run `orun auth login` or `orun auth login --device`.
- Missing repo link: tell the user to run `orun cloud link`; if the backend has not linked the repo yet, tell the user to link it in the Orun dashboard first.
- Missing tools: name the missing tool and how to install or provide it.

Also fix cleanup:

- Track background PIDs.
- On `EXIT`, `INT`, and `TERM`, kill any still-running harness child processes before removing temp files.
- Preserve useful logs on failure long enough to print them.
- Do not leave orphaned `orun run` processes after Ctrl-C or early failure.
