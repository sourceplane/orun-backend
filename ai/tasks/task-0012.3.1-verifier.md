# Objective

Verify that local `orun run --remote-state` now uses the secure user-local namespace flow:

```text
local:user:<githubUserId>:repo:<repoId>
```

The user's original failure must be gone:

```text
Error: initializing remote run: init run: create run: Session creates require namespaceId (code: INVALID_REQUEST)
```

For authenticated local runs with a GitHub remote, the CLI must auto-resolve local namespace metadata through the backend session endpoint, persist local namespace metadata safely, send `repoFullName` to run creation, and never reuse canonical repo namespace IDs for local remote-state.

## 2. Backend Client Contract

Verify `internal/cliauth/backend.go`:

- `LinkRepoFromSessionResponse` includes `namespaceKind`, `namespaceId`, `namespaceSlug`, `repoId`, `repoFullName`, and `linkedAt`.
- `LinkRepoFromSession` calls `POST /v1/accounts/repos/link`.
- It sends `Authorization: Bearer <accessToken>`.
- It sends JSON body `{ "repoFullName": "owner/repo" }`.
- It parses typed backend errors into `*APIError`.
- It rejects a session-link response where `namespaceKind != "local"`.
- It does not add or suggest GitHub PAT support.

Review tests for success, backend typed errors, auth header/body shape, and non-local response rejection.

## 3. Config and Cache Safety

Verify local config handling:

- `RepoLink` or equivalent persists backend URL, repo full name, namespace kind, local namespace ID, repo ID, and linked timestamp.
- Existing cached namespace IDs that are canonical/numeric/`repo:` are invalidated for local remote-state.
- Local remote-state does not use old canonical namespace IDs for run creation.
- Cache lookup is scoped by backend URL and repo full name so different backends/repos do not collide.
- Config writes do not store tokens.

Security-critical check: stale commits in PR #85 mention old `allowedNamespaceIds` behavior. Ensure final docs/messages/tests no longer describe "any authenticated CLI session can link any known slug" as acceptable. The CLI should describe the backend as deriving user-local namespace IDs from the authenticated user and repo cache.

## 4. `orun cloud link`

Verify `cmd/orun/command_cloud.go`:

- `orun cloud link --backend-url <url>` is supported.
- It ensures local Orun auth exists and refreshes access tokens when needed.
- It detects the current GitHub remote.
- It calls the session link endpoint, not the dashboard/admin GitHub-token route.
- It requires `namespaceKind: "local"` in the response.
- It persists full local namespace metadata.
- Output is concise and does not print tokens.
- Errors are actionable for:
  - missing backend support or old backend response shape
  - unknown repo/cache miss
  - forbidden access
  - missing auth
  - missing GitHub remote
- It never asks for or suggests a GitHub PAT.

## 5. `orun run --remote-state`

Verify local auto-resolution outside GitHub Actions:

- Detects the current GitHub repo and repo full name.
- Checks cached local namespace metadata first.
- On cache miss, stale cache, or canonical cache, calls `POST /v1/accounts/repos/link`.
- Persists the returned local namespace metadata.
- Sends `repoFullName` in `CreateRunRequest` so the backend can derive local namespace server-side.
- Uses the same effective local namespace context for claim, update, heartbeat, runnable, status, and log requests.
- Does not surface raw `Session creates require namespaceId` as the primary user-facing error.
- Produces clear missing-login and missing-remote errors.
- Translates backend `NOT_FOUND`, `FORBIDDEN`, and `INVALID_REQUEST` into actionable messages.

Verify GitHub Actions path:

- OIDC behavior is unchanged.
- No local config lookup is required in GHA.
- No session link endpoint is called in GHA.
- No local namespace ID is sent in GHA.

## 6. `ORUN_TOKEN` Safety

Verify the advanced token path:

- `ORUN_TOKEN` outside GitHub Actions does not infer repo identity from an arbitrary token.
- It calls the session link endpoint only if the code can safely treat the token as an Orun CLI session token, or it requires cached local namespace metadata.
- Missing cache/auth produces a clear `orun auth login` or explicit-token limitation message.
- Docs do not present `ORUN_TOKEN` as a GitHub PAT replacement.
