# Objective

Implement the first production-grade self-hosted backend bootstrap slice in the `orun` CLI.

After this task, a user with a Cloudflare account and API token should be able to run:

```bash
orun backend init
orun backend status
orun backend destroy
```

to provision, inspect, and intentionally remove an Orun backend composed of:

- Cloudflare Worker script
- Durable Object bindings/classes
- D1 database and schema migrations
- R2 bucket
- required Worker vars/secrets where provided or generated

The implementation must be idempotent, testable without real Cloudflare credentials, and safe around secrets and destructive operations.

## 2. Cloudflare REST Client

Add a focused Cloudflare API client in Go.

Required:

- Uses `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` by default.
- Supports explicit flags/env override for account ID and API token.
- Sets `Authorization: Bearer <token>`.
- Uses a clear `User-Agent` like `orun-cli/<version>`.
- Has injectable HTTP client/base URL for tests.
- Parses Cloudflare API error envelopes into typed/actionable errors.
- Never logs or prints API tokens or secrets.

Required capabilities:

- List/create/delete D1 database by name.
- Apply bundled D1 migrations in deterministic order.
- List/create/delete R2 bucket by name.
- Upload/update Worker module script with correct bindings.
- Set non-secret Worker vars.
- Set Worker secrets when values are supplied or generated.
- Fetch status for Worker/D1/R2/migration readiness.

Use official Cloudflare REST APIs. Do not shell out to `wrangler` except in docs or optional manual verification.

## 3. `orun backend init`

Add a new root command group:

```text
orun backend
```

Add:

```bash
orun backend init
```

Required behavior:

- Reads Cloudflare credentials from env or flags.
- Creates or reuses the D1 database by name.
- Creates or reuses the R2 bucket by name.
- Applies bundled migrations exactly once and in order.
- Uploads/updates the Worker script with bindings to the provisioned D1/R2/DO resources.
- Configures required Worker vars:
  - `GITHUB_JWKS_URL`
  - `GITHUB_OIDC_AUDIENCE`
  - `ORUN_PUBLIC_URL` when known or provided
  - `ORUN_DASHBOARD_URL` when provided
- Configures Worker secrets:
  - `ORUN_SESSION_SECRET` should be accepted from env/flag or generated securely if absent.
  - `GITHUB_CLIENT_ID` and `GITHUB_CLIENT_SECRET` should be set if provided; if absent, init should finish with a clear warning that dashboard/CLI OAuth requires a GitHub OAuth app before auth works.
- Prints a concise success summary with resource names, Worker URL if discoverable, and any manual follow-up steps.
- Stores non-secret bootstrap metadata in local Orun config so `status`, `destroy`, and `auth/cloud` commands can find the default backend URL.
- Is idempotent: running `init` twice should not create duplicate resources or fail on already-existing resources.
- Supports a `--dry-run` mode that prints the planned actions without touching Cloudflare.
- Supports machine-readable `--json` output.

Suggested flags:

```text
--account-id
--api-token
--name                 default orun-api
--d1-name              default orun-db
--r2-bucket            default orun-storage
--oidc-audience        default orun
--public-url
--dashboard-url
--github-client-id
--github-client-secret
--session-secret
--dry-run
--json
```

Avoid printing secret values in both text and JSON output.

## 4. `orun backend status`

Add:

```bash
orun backend status
```

Required behavior:

- Reads stored bootstrap metadata and/or flags.
- Checks Worker script existence.
- Checks D1 database existence.
- Checks applied migration readiness.
- Checks R2 bucket existence.
- Checks whether required vars/secrets appear configured without revealing values.
- Shows the effective backend URL when known.
- Exits non-zero when required resources are missing or incompatible.
- Supports `--json`.

Status must be safe to run in CI and must not require destructive permissions beyond read/list access where Cloudflare supports narrower permissions.

## 5. `orun backend destroy`

Add:

```bash
orun backend destroy
```

Required behavior:

- Destructive by default only after explicit confirmation.
- Requires `--yes` for non-interactive execution.
- Refuses to delete resources that are not recorded as managed by `orun backend init` unless `--adopted` or equivalent explicit override is provided.
- Deletes Worker script, D1 database, and R2 bucket in a safe order.
- Warns that D1/R2 data deletion is irreversible.
- Supports `--dry-run`.
- Supports `--json`.
- Does not delete GitHub OAuth app configuration, because that is outside Cloudflare.

Do not make `destroy` easy to run accidentally.

# Integration Notes

- `sourceplane/orun-backend/apps/worker/wrangler.jsonc` is the source of binding names and default resource names.
- The current Worker requires Durable Object migrations for `RunCoordinator` and `RateLimitCounter`.
- D1 migrations are plain SQL and must be applied in lexical order.
- If the Cloudflare API does not expose Wrangler's migration ledger directly, implement a small Orun bootstrap migration ledger table and document it. Do not mark a migration applied unless its SQL succeeded.
- `ORUN_PUBLIC_URL` should match the deployed Worker URL when known. If Cloudflare returns a workers.dev route, use it; otherwise require/provide `--public-url`.
- `ORUN_DASHBOARD_URL` is optional for API-only or remote-state-only installs, but dashboard OAuth will not work without it.
- GitHub OAuth app creation is out of scope; emit clear follow-up instructions instead.
- Use `httptest.Server`/fake transports for Cloudflare client tests.
