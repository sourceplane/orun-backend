# Required Outcomes

## 1. Auth Commands

Add:

```bash
orun auth login
orun auth login --device
orun auth status
orun auth logout
orun auth token --audience orun-backend
```

Behavior:

- `orun auth login` starts a local loopback listener, opens the browser, receives Orun credentials, stores them, and shuts down cleanly.
- `orun auth login --device` starts backend-mediated device login, prints the user code and verification URL, polls until success/denial/expiry, and stores Orun credentials.
- `orun auth status` prints GitHub login, backend URL, token expiry, and whether the current Git remote appears authorized.
- `orun auth logout` revokes the backend refresh token and removes local credentials.
- `orun auth token --audience orun-backend` prints a short-lived Orun access token only when explicitly requested.

## 2. Credential Storage

Implement a small credential manager:

- Prefer OS keychain/credential store when available.
- Fall back to `~/.orun/credentials.json` with `0600` permissions.
- Store Orun access token, access expiry, refresh token, refresh expiry, GitHub login, and backend URL.
- Store non-secret config such as backend URL in `~/.orun/config.yaml` if that matches repo conventions.
- Never store GitHub OAuth access tokens or GitHub PATs.

## 3. `orun cloud link`

Add:

```bash
orun cloud link
```

Behavior:

- Ensure login, launching `orun auth login` if interactive and missing.
- Detect the current GitHub remote.
- Verify the repo namespace is present in the Orun session or linked account.
- Persist backend URL/repo link locally.
- Print a concise success or a clear remediation path.

## 4. Remote-State Token Resolution

Update the remote-state HTTP client/auth resolver:

1. In GitHub Actions, keep using GitHub OIDC from `ACTIONS_ID_TOKEN_REQUEST_URL`.
2. Outside GitHub Actions, use stored Orun CLI access token.
3. If access token is expired, refresh it with the stored Orun refresh token.
4. If no login exists and interactive, prompt to run or start `orun auth login`.
5. If no login exists and non-interactive, fail with a clear message mentioning `orun auth login --device` or explicit `ORUN_TOKEN`.
6. Keep `ORUN_TOKEN` as explicit short-lived Orun machine-token fallback for unknown CI, not as a GitHub PAT path.

Local `orun run <planID> --remote-state` must then call the same claim/update/heartbeat/runnable/log APIs as GitHub Actions.
