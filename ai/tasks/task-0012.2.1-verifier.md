# Required Verification Work

## 1. Namespace Model and Compatibility

Verify the implementation has a single consistent namespace model.

Required:

- `local` namespace IDs are exactly server-derived from signed `githubUserId` plus backend-cached `repoId`.
- CLI clients cannot choose or override `githubUserId`, `repoId`, or a canonical repo namespace ID.
- Canonical repo namespaces are OIDC-only.
- If the implementation uses a `repo:<githubRepoId>` prefix for canonical repo namespaces, confirm specs/types/storage/DO keys/OIDC handling/tests were updated consistently and that existing rows/default migrations remain safe. If the task/spec still requires raw GitHub repo ID as canonical namespace ID and the implementation silently changed it, require either a spec update/proposal or a compatibility fix before PASS.
- Local and repo namespaces with the same `runId` cannot collide in D1, Durable Objects, or R2 paths.

## 2. Migration and Data Model

Verify `migrations/0004_local_namespaces.sql` or equivalent:

- Adds immutable GitHub user ID storage for accounts.
- Adds a namespace kind discriminator or an equally strict local/repo distinction.
- Adds `account_repo_cache` or equivalent account-scoped repo cache.
- Uses numeric GitHub `repo_id` as the authorization input for local namespace derivation.
- Keeps existing `namespaces`, `accounts`, and `account_repos` data valid.
- Does not store GitHub OAuth access tokens, PATs, Orun access tokens, or refresh tokens in plaintext.
- Can be applied idempotently through the repo's Cloudflare D1 migration process.

If the live database migration is part of the deployment, verify it actually ran. Use Wrangler/D1 commands appropriate for the repo, for example inspect `wrangler.toml`, list migrations, and confirm the live DB has the new schema. Do not print secrets.

## 3. Auth and Session Claims

Verify OAuth and device login:

- Capture immutable numeric GitHub user ID from GitHub `/user`.
- Store the GitHub user ID on the account or equivalent durable row.
- Include `githubUserId` in signed CLI session access tokens.
- Refresh-token exchange preserves or rehydrates `githubUserId`.
- Old CLI sessions without `githubUserId` fail closed with a useful re-login message.
- Dashboard sessions remain read-oriented and cannot mutate coordination routes.
- GitHub OAuth tokens are discarded after repo cache refresh.

## 4. Account-Scoped Repo Cache

Verify local repo resolution uses only caller-owned cache:

- Login refreshes `(account_id, repo_id, repo_full_name)` for repos visible to that GitHub user.
- `POST /v1/accounts/repos/link` looks up `repoFullName` in the caller's account-scoped cache.
- The handler does not authorize from global `namespaces` slug lookup.
- A repo slug that exists globally but not in the caller's cache returns typed `NOT_FOUND` or `FORBIDDEN`.
- Repo display slugs can change safely because namespace derivation uses numeric IDs.

Search specifically for risky patterns:

```bash
rg -n "lookupNamespaceBySlug|allowedNamespaceIds|account_repo_cache|repoFullName|namespace_kind|local:user|repo:" apps packages migrations
```

If `lookupNamespaceBySlug` or global namespace lookup appears in the CLI session link path, inspect carefully. FAIL if it authorizes session access.

## 5. Link Endpoint Behavior

Verify `POST /v1/accounts/repos/link`:

- Requires session auth and `sessionKind="cli"`.
- Rejects dashboard sessions.
- Rejects missing `githubUserId` with `FORBIDDEN` and re-login guidance.
- Validates `repoFullName`.
- Resolves repo only from account-scoped cache.
- Derives `namespaceId = local:user:<githubUserId>:repo:<repoId>`.
- Upserts/returns `namespaceKind: "local"`, `namespaceId`, `namespaceSlug`, `repoId`, `repoFullName`, and `linkedAt`.
- Is idempotent for the same user/repo.
- Returns different local namespaces for two users linking the same repo.
- Does not require or accept a GitHub PAT on the CLI session path.
- Does not leak internal D1 errors.

## 6. Run Creation and Mutable Coordination

Verify `POST /v1/runs`:

- OIDC creates derive canonical repo namespace from verified OIDC claims.
- OIDC rejects mismatched request namespace values.
- CLI session creates require `sessionKind="cli"` and derive local namespace from `repoFullName` or verify an exact local namespace reference.
- CLI session creates reject canonical repo namespace IDs.
- CLI session creates reject another user's `local:user:` namespace.
- Deterministic `runId` idempotency is scoped by effective namespace.

Verify claim/update/heartbeat/runnable/status/log paths:

- Resolve the run under the effective namespace before touching DO/R2/D1.
- Reject CLI sessions that do not match the run's local namespace prefix.
- Reject CLI sessions against canonical repo namespaces.
- Reject OIDC access to local namespaces.
- Preserve `runnerId` forwarding and existing coordinator semantics.

## 7. Types, Client, and Specs

Verify:

- Shared `Namespace` type or equivalent exposes namespace kind.
- `SessionClaims` includes immutable `githubUserId`.
- `CreateRunRequest` includes `repoFullName` or equivalent local derivation input.
- `LinkRepoFromSessionResponse` includes `namespaceKind`, `repoId`, and `repoFullName`.
- `packages/client/src/index.ts` returns the new link response shape.
- Existing dashboard/admin `linkRepo(repoFullName, githubAccessToken)` remains intact.
- `spec/04-worker-api.md` and `spec/09-cli-integration.md` match implementation. If implementation intentionally differs, require a proposal/spec update before PASS.
