# Required Verification Work

## 1. Original Blocker Recheck

Review `handleCatalogSync` in `apps/worker/src/handlers/catalog.ts`.

Required:

- `envelope.components` must be rejected unless it is an array.
- Every component must require `component.path`.
- Missing `component.path` must return `400` with typed JSON code `INVALID_REQUEST`.
- Non-string `component.path` values such as `null`, numbers, booleans, arrays, and objects must return `400` with typed JSON code `INVALID_REQUEST`.
- Existing invalid path checks still reject empty strings, absolute paths, and `..` traversal.
- Validation must run before:
  - `db.uploadExists`
  - `db.recordCatalogUpload`
  - any R2 catalog write
  - `rc.ctx.waitUntil`
  - the final `202` response
- The implementation must not rely on async normalization to discover schema errors.

FAIL if an envelope with omitted or non-string `component.path` can still return `202`.

## 2. Regression Test Coverage

Inspect and run the catalog tests.

Required tests:

- Missing `component.path` returns `400 INVALID_REQUEST`.
- Non-string `component.path` returns `400 INVALID_REQUEST`.
- Non-array `components` returns `400 INVALID_REQUEST`.
- Invalid missing/non-string path requests do not call `ctx.waitUntil`.
- Invalid envelopes do not write raw catalog payloads to R2.
- Empty `components: []` remains valid if the implementation intentionally supports it and returns `202` with `componentCount: 0`.
- Existing Task 0013 success, auth, repo mismatch, path traversal, R2 write, D1 normalization, idempotency, read-isolation, and client tests still pass.

If the code clearly prevents R2 writes by returning before `ctx.waitUntil`, but a test only asserts `waitUntil` for part of the invalid-envelope matrix, decide whether that is enough. Add a small verifier-owned regression test if the proof is too implicit.

## 3. API and Auth Contract Regression

Verify Task 0013 public API behavior remains intact:

- `POST /v1/catalog/sync` still requires OIDC auth.
- Dashboard and CLI sessions still cannot publish canonical catalog state.
- OIDC `repository_id` must still match `envelope.source.repoId`.
- OIDC `repository` must still match `envelope.source.repo`.
- Valid catalog sync fixtures still return `202 CatalogSyncAccepted`.
- Duplicate `uploadId` behavior remains idempotent.
- Catalog session read endpoints still use linked canonical repo visibility and do not expose local CLI namespaces.
- Typed error envelopes remain consistent with the rest of the Worker.

Do not expand this task into dashboard UI work or a catalog storage redesign.
