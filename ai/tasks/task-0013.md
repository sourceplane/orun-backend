# Required Outcomes

## 1. Shared Catalog Contracts

Update `@orun/types` with the catalog types from the specs:

- `CatalogSyncEnvelope`
- `ComponentState`
- `CatalogSyncAccepted`
- `CatalogComponentSummary`
- `CatalogComponentDetail`
- `CatalogComponentEvent`
- `CatalogComponentRelation`
- `CatalogComponentListResponse`
- `CatalogComponentRelationsResponse`

Add path helpers:

- `catalogEnvelopePath(namespaceId, uploadId)`
- `catalogComponentStatePath(namespaceId, commitSha, componentName)`

Keep the package type-only except for existing path helper functions.

## 2. Catalog D1 Migration

Add `migrations/0005_catalog_index.sql` with tables and indexes from `spec/12-catalog-index.md`:

- `catalog_uploads`
- `catalog_components`
- `catalog_component_relations`
- `catalog_component_events`

Use a deterministic `relation_id` rather than SQLite expression primary keys.

## 3. Storage Helpers

Extend `packages/storage` with focused catalog support:

- record catalog uploads idempotently by `uploadId`
- upsert component rows
- replace relation rows for a component
- append component event rows when appropriate
- list visible components with filters
- get one component detail by visible namespace set
- list component events
- list component relations, including incoming dependents

D1 is only an index. Raw envelopes and component state snapshots must go to R2.

## 4. Worker API

Add routes and handlers:

```text
POST /v1/catalog/sync
GET  /v1/catalog/components
GET  /v1/catalog/components/:componentId
GET  /v1/catalog/components/:componentId/history
GET  /v1/catalog/components/:componentId/runs
GET  /v1/catalog/components/:componentId/dependencies
GET  /v1/repos/:repoId/components
```

For `POST /v1/catalog/sync`:

- require OIDC auth
- reject dashboard and CLI sessions
- require OIDC `repository_id` and `repository` claims to match the envelope source
- validate schema version, upload ID, repo fields, component IDs/names, component paths, and body size
- store the raw envelope in R2
- normalize D1 rows
- return `202 CatalogSyncAccepted`
- treat duplicate `uploadId` as idempotent success

For catalog reads:

- require a session
- resolve visible canonical repo namespace IDs from linked repos
- never return canonical catalog rows outside the linked set
- do not include local CLI namespaces in catalog results

## 5. Client SDK

Add typed `@orun/client` methods for the catalog endpoints. Keep API error behavior consistent with existing methods.

## 6. Tests

Add or update tests for:

- catalog path helpers
- migration shape where practical
- OIDC catalog sync success
- OIDC repo ID mismatch rejected
- OIDC repo slug mismatch rejected
- dashboard/CLI session catalog writes rejected
- duplicate upload ID idempotence
- invalid component path rejected (`..`, absolute path, empty path)
- raw envelope stored in R2
- normalized component/relation/event rows written to D1
- catalog list filters call/query D1 correctly
- linked-repo read isolation
- `@orun/client` catalog methods build expected requests

# Integration Notes

- Existing `namespaces.namespace_kind` defaults to `repo`; catalog sync should upsert canonical repo namespaces as `kind: "repo"`.
- Existing dashboard read policy uses linked account repos. Reuse that policy for catalog reads instead of inventing a separate authorization surface.
- The current `account_repos` table stores namespace IDs, not repo IDs. If repo filtering needs repo ID lookup, join through `namespaces`/catalog rows carefully and keep namespace isolation explicit.
- `runs` and `jobs` already exist. Component recent-runs can start as a best-effort query by component name/job component and namespace, but document any limitation in the implementer report.

# Acceptance Criteria

- `POST /v1/catalog/sync` accepts a valid OIDC envelope fixture and returns `202`.
- The raw envelope is written to an R2 key starting with the canonical repo namespace ID.
- D1 contains queryable component, relation, upload, and event rows after sync.
- Session catalog reads only return components from linked canonical repo namespaces.
- Duplicate `uploadId` returns success without duplicate component events.
- Invalid auth and invalid path/security cases return typed JSON errors.
- `@orun/client` exposes typed catalog methods used by tests.
- Existing run/job/log/auth/account tests remain green.
