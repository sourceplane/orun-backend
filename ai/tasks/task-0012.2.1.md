# Current Repo Context

Task 0012.2 was merged and deployed far enough for the CLI to call a session repo-link endpoint, but verification failed because the backend allowed a local CLI session to resolve a GitHub repo slug into the canonical repo namespace.

The failed verifier found this unsafe state:

- `POST /v1/accounts/repos/link` could accept any known `repoFullName` from an authenticated CLI session.
- A follow-up change removed the `allowedNamespaceIds` guard.
- A user could therefore guess or reuse a globally known repo slug and create local remote-state runs in that repo's canonical namespace.

That model is rejected. Canonical repo namespaces are for verified workload identity only.

# Objective

Redesign and implement backend namespace resolution so:

- GitHub Actions OIDC writes only to the canonical repo namespace derived from verified OIDC `repository_id`.
- Local OAuth/device-authenticated CLI sessions write only to a user-scoped local namespace derived server-side as:

```text
local:user:<githubUserId>:repo:<repoId>
```

Local runs must stay with the authenticated user. They must not be clubbed with repo job execution or mutate the repo namespace used by GitHub Actions.

# Required Security Model

Think in two identities:

| Identity | Auth proof | Namespace | Write authority |
|----------|------------|-----------|-----------------|
| Repo workload | GitHub Actions OIDC with verified `repository_id` and `repository` | Canonical repo namespace, usually the GitHub repo ID | CI/workload runs only |
| Human local CLI | Orun CLI session issued after GitHub OAuth/device login | `local:user:<githubUserId>:repo:<repoId>` | Local developer remote-state sandbox only |

Security invariants:

- A session token can never create, claim, update, heartbeat, or upload logs in a canonical repo namespace.
- The namespace ID for a local run is derived by the Worker from signed session claims and backend-cached GitHub repo IDs.
- The client may send `repoFullName`; it may not choose the user ID, repo ID, or canonical namespace ID.
- Repo slug resolution for CLI sessions must use the caller's account-scoped repo cache, not the global `namespaces` table.
- If the repo is not in the caller's cache, return a typed `NOT_FOUND` or `FORBIDDEN` with re-login/access guidance. Do not fall back to global slug lookup.
- Future "local user may write repo namespace" behavior requires an explicit repo-delegation policy table and is out of scope for this task.

# Required Outcomes

## 1. Add Durable Identity and Repo Cache

Add the minimum D1 schema needed to support server-derived local namespaces.

Required data:

- `accounts.github_user_id` or equivalent immutable numeric GitHub user ID storage.
- CLI session records and signed session claims include the immutable GitHub user ID.
- Account-scoped repo cache, for example `(account_id, repo_id, repo_full_name, permissions_json, last_seen_at)`.
- Local namespace rows are distinguishable from canonical repo namespace rows. This can be a `namespace_kind` column, a companion metadata table, or a rigorously validated ID prefix, but tests must prove sessions cannot write repo namespaces.

Migration requirements:

- Backfill safely where possible.
- Keep existing dashboard/admin repo linking functional.
- Do not store GitHub OAuth access tokens or PATs.
- Keep repo slug/display name mutable; use numeric `repo_id` for authorization and namespace derivation.

## 2. Update OAuth and Device Login

Update backend-mediated GitHub login so it captures:

- GitHub numeric user ID.
- GitHub login for display/audit only.
- Repos visible to the authenticated user, with numeric repo IDs and full names.

The account-scoped repo cache is refreshed during browser OAuth and device flow. If repo visibility changes, re-running `orun auth login` should refresh the cache.

Dashboard/admin repo linking may keep stronger admin checks. Local remote-state only needs enough verified repo identity to construct a user-local namespace; do not give the user repo namespace write authority.

## 3. Redesign `POST /v1/accounts/repos/link`

Keep the route path for CLI compatibility, but change the semantics:

```http
POST /v1/accounts/repos/link
Authorization: Bearer <orun-cli-session-token>
Content-Type: application/json

{ "repoFullName": "owner/repo" }
```

Successful response:

```json
{
  "namespaceKind": "local",
  "namespaceId": "local:user:123456:repo:987654321",
  "namespaceSlug": "local:octocat/owner/repo",
  "repoId": "987654321",
  "repoFullName": "owner/repo",
  "linkedAt": "..."
}
```

Behavior:

- Require `sessionKind="cli"`.
- Validate `repoFullName`.
- Resolve the repo only from the caller's account-scoped repo cache.
- Derive `namespaceId` server-side from signed `githubUserId` and cached `repoId`.
- Upsert the local namespace and account-local repo link idempotently.
- Return `namespaceKind="local"`.
- Reject dashboard sessions.
- Reject unknown repos with typed guidance to re-run `orun auth login` or fix GitHub access.
- Do not read the global `namespaces` table as an authorization source for local sessions.
- Do not return canonical repo namespace IDs to CLI sessions.

## 4. Redesign Session `POST /v1/runs`

Fix the current local error:

```text
Session creates require namespaceId (code: INVALID_REQUEST)
```

New behavior:

- OIDC creates derive the canonical repo namespace from verified OIDC claims.
- Session creates require `sessionKind="cli"` and derive the local namespace from `repoFullName` or a previously returned local namespace reference.
- If a session request includes a `namespaceId`, accept it only when it exactly equals the server-derived local namespace for that session and repo.
- Reject session attempts to create under numeric/canonical repo namespace IDs.
- Persist the effective namespace kind and ID with the run.
- Ensure deterministic `runId` idempotency remains scoped by effective namespace.

## 5. Enforce Namespace Access Everywhere

Update mutable and read paths so namespace resolution is explicit and safe:

- Claim, update, heartbeat, runnable, status, and log endpoints must resolve the target run under the effective namespace before touching Durable Objects, R2, or D1.
- CLI local requests must include enough context for the Worker to derive or verify the local namespace. Prefer `repoFullName`; a cached local namespace reference is acceptable only with exact server verification.
- OIDC requests must never access local namespaces.
- Dashboard sessions remain read-oriented and must not use the CLI local write policy.
- R2 and Durable Object keys must use the effective namespace ID, so local and repo runs with the same `runId` cannot collide.

## 6. Update Types and Client Package

Update shared types to represent:

- `Namespace.kind` or equivalent.
- CLI session claims with immutable `githubUserId`.
- Link response with `namespaceKind`, `repoId`, and `repoFullName`.
- Create-run request fields needed for local namespace derivation, such as `repoFullName`.

Update `/Users/irinelinson/sourceplane/orun-backend/packages/client/src/index.ts` to match the new response shape. Keep existing dashboard/admin link APIs intact.

## 7. Tests

Add or update tests for:

- OAuth and device login store immutable GitHub user ID and account-scoped repo cache entries.
- `POST /v1/accounts/repos/link` returns a local namespace for a CLI session.
- Link endpoint is idempotent for the same user/repo.
- Two users linking the same repo get different local namespace IDs.
- A user cannot link a repo that is not in that user's repo cache, even if the repo slug exists globally.
- Session create-run with `repoFullName` derives the local namespace.
- Session create-run rejects canonical repo namespace IDs.
- Session create-run rejects a mismatched local namespace ID.
- OIDC create-run still uses canonical repo namespace and rejects mismatched request namespace IDs.
- Claim/update/heartbeat/log upload reject session attempts against canonical repo namespaces.
- Dashboard sessions remain read-only.
