# Required Outcomes

## 1. Update Backend Client Types

Update the CLI backend client for the new link response:

```json
{
  "namespaceKind": "local",
  "namespaceId": "local:user:123456:repo:987654321",
  "namespaceSlug": "local:octocat/owner/repo",
  "repoId": "987654321",
  "repoFullName": "owner/repo",
  "linkedAt": "..."
}
```

The client should reject or ignore any session-link response that does not return `namespaceKind: "local"`.

## 2. Update Local Config and Cache Semantics

Persist local remote-state link data with enough context to avoid confusing old repo namespace caches with new local namespaces:

- backend URL
- repo full name
- repo ID if returned
- namespace kind
- local namespace ID
- linked timestamp

If existing config contains a numeric/canonical namespace ID for local remote-state, invalidate it and relink. Do not use old canonical repo namespace IDs for local run creation.

## 3. Make `orun cloud link` Local-Namespace Aware

`orun cloud link` should:

- Ensure Orun CLI auth exists or start/login as appropriate.
- Detect the current GitHub remote.
- Call `POST /v1/accounts/repos/link`.
- Require `namespaceKind: "local"` in the response.
- Persist local namespace metadata.
- Print a concise summary that makes clear the link is for local remote-state.

Failure messages:

- Missing backend support: say the backend must include Task 0012.2.1.
- Unknown repo/cache miss: ask the user to re-run `orun auth login` or verify GitHub repo access.
- Forbidden: explain which repo was detected and which GitHub login is active if available.
- Never ask for or suggest a GitHub PAT.

## 4. Auto-Resolve Local Namespace During `orun run --remote-state`

Outside GitHub Actions:

1. Detect the current GitHub repo.
2. Load cached link data.
3. If cache is missing, stale, or canonical, call the link endpoint.
4. Create the run by sending the backend-required local namespace context. Prefer `repoFullName` so the Worker can derive the namespace; send cached local namespace ID only when the backend contract requires it and verify `namespaceKind`.
5. Use the same effective namespace context on claim, update, heartbeat, runnable, status, and log requests.

In GitHub Actions:

- Keep OIDC unchanged.
- Do not call the local session link endpoint.
- Do not require local config.
- Do not send local namespace IDs.

The raw backend error `Session creates require namespaceId` should not be surfaced as the main user-facing error. Replace it with a clear auto-resolution or backend-version message.

## 5. Keep `ORUN_TOKEN` Safe

If `ORUN_TOKEN` is used outside GitHub Actions:

- Treat it as an explicit advanced path.
- Call the link endpoint only if the token is known to be an Orun CLI session token and backend errors confirm that flow.
- Otherwise require valid cached local namespace metadata or fail with a clear message that local remote-state auto-resolution requires `orun auth login`.

Do not infer GitHub repo identity from an arbitrary machine token.

## 6. Update Local Harness and Docs

Fix the local harness regression called out by Task 0012.3 verification:

- `examples/remote-state-matrix/run-local-harness.sh` must not preflight-fail only because the repo is not already cached.
- The harness may run `orun cloud link` for diagnostics, but it should let the normal auto-resolution path run.
- Docs should show the happy path:

```bash
orun auth login
orun run --remote-state -i examples/intent.yaml --dry-run
```

Docs must explain:

- GitHub Actions uses OIDC and canonical repo namespace.
- Local developer runs use Orun CLI auth plus Git remote, and coordinate under `local:user:<githubUserId>:repo:<repoId>`.
- Local state is intentionally separate from repo CI job execution.
- No GitHub PAT is required.
