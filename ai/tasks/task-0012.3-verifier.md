## 3. `orun cloud link`

Verify:

- `orun cloud link --backend-url <url>` is registered on the cloud link command, not only the auth command
- local session is loaded and refreshed if expired
- current GitHub remote is detected
- CLI calls the new session link endpoint rather than the old dashboard-only list fallback
- returned namespace link is persisted to `~/.orun/config.yaml`
- output is concise and does not print tokens
- errors are actionable:
  - backend route missing or `HTTP_404`
  - unknown slug / stale session
  - unauthorized or missing auth
  - no GitHub remote

Security check:

Do not let CLI docs/messages normalize unsafe backend behavior. If backend now permits any CLI session to link any known slug, the CLI should not describe that as a secure authorization model unless Task 0012.2 has an accepted spec change.

## 4. `orun run --remote-state`

Verify local auto-resolution outside GitHub Actions:

- detects current GitHub remote and repo full name
- checks cached repo link first
- on cache miss, uses local Orun CLI session to call `POST /v1/accounts/repos/link`
- persists returned namespace link
- passes non-empty `namespaceId` to remote run creation
- no longer lets the raw backend error `Session creates require namespaceId` be the primary user-facing message
- clear missing-login and missing-remote errors exist
- backend `NOT_FOUND` and `FORBIDDEN` are translated correctly
- stale `allowedNamespaceIds` behavior is intentional and safe

Verify GitHub Actions path:

- OIDC behavior remains unchanged
- no local config lookup is required in GHA
- no session endpoint is called in GHA

Verify `ORUN_TOKEN` path:

- safe behavior is implemented and documented
- static token does not silently call session-only repo-link endpoint unless known to be a CLI session token
- cached namespace or explicit namespace is required when appropriate
