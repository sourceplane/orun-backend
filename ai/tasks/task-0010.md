# Required Outcomes

## 1. CLI Session Token Shape

Extend Orun session JWTs with a session kind:

```ts
sessionKind: "dashboard" | "cli"
tokenUse: "access"
```

Backward compatibility:

- Existing dashboard tokens without `sessionKind` must be treated as dashboard/read-oriented.
- Dashboard session behavior must not regress.
- CLI sessions are the only session tokens allowed on mutable coordination routes.

## 2. CLI Browser OAuth Loopback

Extend `GET /v1/auth/github` to support:

```text
GET /v1/auth/github?client=cli&returnTo=http://127.0.0.1:<port>/callback/<nonce>
```

Requirements:

- Accept only loopback `http://127.0.0.1:<port>` or `http://localhost:<port>` return URLs for `client=cli`.
- Bind `client`, `returnTo`, and nonce-bearing callback path into signed state.
- Reject non-loopback CLI `returnTo` values with `INVALID_REQUEST`.
- Keep dashboard `ORUN_DASHBOARD_URL` origin validation unchanged.
- Keep no-`returnTo` JSON callback compatibility unchanged.
- Never return or store GitHub OAuth access tokens.

## 3. Device Login Endpoints

Add backend-mediated GitHub device flow endpoints:

```text
POST /v1/auth/cli/device/start
POST /v1/auth/cli/device/poll
```

Behavior:

- Start calls GitHub's device authorization endpoint and returns `deviceCode`, `userCode`, verification URLs, expiry, and interval.
- Poll exchanges the device code with GitHub through the backend.
- Pending authorization returns `202`.
- `slow_down`, expiry, denial, and malformed states return typed errors.
- Successful poll issues Orun CLI credentials and never returns the GitHub access token.
- Rate-limit start/poll by IP and device code.

## 4. Refresh and Logout

Add endpoints:

```text
POST /v1/auth/cli/token
POST /v1/auth/cli/logout
```

Requirements:

- On login, issue a 1-hour Orun access token plus an opaque refresh token.
- Store only a cryptographic hash of the refresh token in D1.
- Refresh mints a new short-lived access token from the stored session snapshot.
- Expired or revoked refresh tokens cannot mint access tokens.
- Logout revokes the refresh token.
- Refresh tokens are never accepted on normal API routes.

## 5. Storage

Add migration:

```text
migrations/0003_cli_sessions.sql
```

Implement D1 helpers for creating, reading by refresh hash, marking used, revoking, and GC-safe expiry handling.

## 6. Mutable Route Authorization

Allow these routes for GitHub OIDC or CLI session auth:

- `POST /v1/runs/:runId/jobs/:jobId/claim`
- `POST /v1/runs/:runId/jobs/:jobId/update`
- `POST /v1/runs/:runId/jobs/:jobId/heartbeat`
- `GET /v1/runs/:runId/runnable`
- `POST /v1/runs/:runId/logs/:jobId`

Dashboard sessions must receive `403 FORBIDDEN` on these mutable routes.

Namespace access must still be enforced for CLI sessions. The human actor should be recorded on run/job metadata where the existing model supports it.

Update specs/docs only as needed to match the implemented behavior. Do not rewrite old specs wholesale.
