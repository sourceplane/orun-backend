# Required Outcomes

## 1. Local Harness

Add a local script or documented command set, preferably under:

```text
examples/remote-state-matrix/
```

It should:

- require `orun auth login` or `orun auth login --device`
- use `ORUN_BACKEND_URL=https://orun-api.sourceplane.ai` by default, with override
- compile or reuse one plan
- set a shared `ORUN_EXEC_ID`
- launch multiple local `orun run <planID> --remote-state --job ...` processes
- include at least one duplicate job target
- include at least one dependency-wait case
- verify final status from a separate command
- fetch at least one job log from a separate command

## 2. Assertions

The harness must fail loudly if:

- both duplicate local processes execute the same job
- dependency waiting fails because local state is empty
- status does not show expected successful jobs
- logs cannot be retrieved
- auth is missing or expired and refresh does not recover

## 3. Docs

Update docs to explain:

- why local remote-state exists
- how it differs from default local filesystem state
- how auth works locally vs GitHub Actions
- how to run the harness
- how to troubleshoot missing repo access, expired tokens, backend URL mismatch, and revoked refresh tokens
- why GitHub PATs are not the normal path

## 4. Optional Mocked CI Guard

If live local auth cannot be automated safely in CI, add a mocked backend or dry-run guard that verifies script structure and command construction without requiring real credentials.
